Architecture tests that read like policy

ArchUnitZig turns a Zig project's imports into an owned dependency graph, then lets ordinary zig test tests enforce boundaries over files, layers, slices, reports, and Zig-native metrics.

Release status ArchUnitZig targets Zig 0.16.0 and is currently pre-release. Pin a reviewed commit when reproducibility matters.

Install from the package manager

Add the package with a stable dependency name. During pre-release development, replace main with a reviewed commit hash in durable projects.

zig fetch --save=archunit git+https://github.com/LukasNiessen/ArchUnitZig.git#main

Run it

zig build test

A passing rule is quiet. A violation returns error.ArchitectureViolation and prints stable, structured evidence through ArchUnitZig's result formatter.

Lazy until the terminal

Selectors and predicates perform no project I/O. check, expectPasses, report rendering, or export is the execution boundary.

Allocator-visible ownership

Builders are independent owned values. Clone explicitly when branching and release every owned stage.

Violations are values

Rules return tagged, inspectable violations before presentation. Tests can assert exact paths, kinds, and dependency evidence.

Zig concepts stay Zig-shaped

Imports, resources, modules, declarations, containers, and coupling replace class-oriented vocabulary that has no honest Zig equivalent.

Choose a domain

Start with file rules for most boundaries, move to named layers for an architectural map, and use testing and diagnostics when integrating the result into a larger suite. The compiler-generated API reference lists the complete public facade.
