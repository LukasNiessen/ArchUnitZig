Query and export dependency graphs

Graph reports expose an owned, stable snapshot for automation and a renderer for human-readable offline artifacts. Querying and presentation remain separate operations.

Create an owned snapshot

projectGraph locates and extracts a project at its terminal. The result owns sorted nodes, edges, import-kind evidence, and a structural summary. Consumers can clone or inspect it without parsing a rendered document.

Focus, closure, and collapse

Start from filename, folder, path, or exact-file seeds. Focus-depth queries retain a bounded neighborhood; incoming and outgoing closure queries follow one dependency direction. Pattern exclusions remove seeds before traversal but do not hide nodes reached from an included seed.

Collapse rules group matching paths under an explicit label after selection. This makes a report legible without changing the extracted dependency graph or the evidence kept on a rendered edge.

Render or export

Rendering returns owned bytes and performs no filesystem writes. Export validates the requested filename, supplies the conventional extension when it is absent, creates parent directories, and propagates I/O failures. HTML output has no remote asset dependency.

Deterministic evidence

Nodes, edges, classification sets, and source locations are normalized and sorted before rendering. Optional generation timestamps can be disabled for golden files. Query operations clone their result so source snapshots and caller contexts may be released independently.

Reports explain; rules enforce Keep release policy in file, layer, slice, or metric rules. Use graph reports to explore a boundary, review a change, and attach concrete topology evidence.
